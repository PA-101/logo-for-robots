MICROCONTROLLER CODE

      
      

        
        
      

    

    
Code for a two-wheeled robot with two PWM motor channels through a motor-driver board. The timing constants are uncalibrated: tune them on your robot.

    

      HARDWARE NOTES
      
What the code assumes

      
    
        
  • Two DC motors through a motor-driver board: one PWM signal (speed) and one direction signal per motor. In C++ you write setMotorPwm; in MicroPython you set the pin numbers at the top.
    • 
        
  • A front bumper switch, and a front distance sensor for if wall-ahead (a placeholder function you fill in).
    • 
        
  • Dead reckoning: every move and turn is timed. There are no wheel encoders, so errors add up over a long program.
    • 
      

      
What to calibrate

      
    
        
  • cm per second at power 100: drive forward for a fixed time on your floor, measure the distance, and set MS_PER_CM to (time in ms) divided by (distance in cm).
    • 
        
  • Turn degrees per second: spin for a fixed time, measure the angle, and set MS_PER_DEG the same way.
    • 
        
  • Battery sag: repeat both measurements with a fuller and an emptier battery. Speed drops as the voltage sags, so calibrate at the charge you will run at, or recalibrate.
    • 
        
  • Distance sensor: check that WALL_AHEAD_CM (35) matches what your sensor reports at that distance.
    • 
      

      
What a real robot adds that the simulator does not

      
    
        
  • Gearbox friction and a dead band: below some duty the wheels do not turn at all, and the two motors rarely match, so the robot drifts sideways.
    • 
        
  • Encoder noise and wheel slip on real floors, if you add encoders later.
    • 
        
  • Sensor noise, motor heating, and battery internal resistance that changes with temperature and age.
